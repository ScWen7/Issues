# 同一订单契约如何组合 Role、Skill 和 Playbook

专题三 B 第三阶段 · 2026-11-15。订单开发者要生成工作簿，独立核验者要确认每个账号能导出哪些订单、付款时间是否正确。以同一个 Issue 决定 D2、同一份 C2 候选分两条角色路径运行，从选材理由追到真实宿主输入，再独立核验工作簿。[架构设计](../../architecture/03b-capability-governance.md) · [一次完整实跑回执](fixtures/role-composition.json)

## 两个角色，十二次派发判断

开发取得 D2、共同业务段落、开发时区章节、开发职责和生成工作簿的 Skill。核验同样取得 D2 和共同约定，角色专用材料换成核验笔记、独立核验职责和读取 XLSX 的 Skill。两个角色都可以选自己的工作方法。表中的字节数仅计入选中的材料正文，按 UTF-8 计算。

| 条件 | 开发，本次预算与结果 | 独立核验，本次预算与结果 | 实际工作回合 |
|---|---|---|---|
| 容纳所有材料 | 707 字节，含“先做东区样本”的 Playbook | 731 字节，含“先比账号再查付款”的 Playbook | 各 1 次 |
| 只够必需项 | 604 字节，保留五项必需材料 | 619 字节，保留五项必需材料 | 各 1 次，均省略可选方法 |

| 另固定了冲突的快速导出 Skill | 786 字节预算，旧法要求省略付款时间 | 810 字节预算，旧法与五列标准冲突 | 0 次；变换选材顺序也得到冲突 |

29 项选材检查覆盖未经签发的 Run、伪造项目或尝试、身份与角色不匹配、读权或执行权缺失、正文或发布清单被改写、重复引用、可选冲突、必需冲突的顺序反转等情形。发布方声明“付款时间列应包含或省略”，实验按这个字段判断冲突。旧 Skill 如列为可选，直接省略；节点明确要求使用时，保留冲突，等待有授权者选择相容版本。这里不评测自由文本理解能力。项目维护者与已有权限以固定身份模拟。[选择模型](../../../prototypes/topic-03b/composition/selection.py) · [订单主入口](../../../prototypes/topic-03b/composition/order_composition.py)

## 一次输入和一次验收各自能证明什么

六个工作回合均由真实 Codex CLI 0.144.6 发往本机 Responses 端点。独立目录校准只看到 Skill 名称、介绍和位置。工作回合显式选择 Skill 后，从原生消息取得完整文件，Role、D2、项目章节和选中的 Playbook 则出现在当前工作指令中。回执逐份核对正文 SHA-256、实际位置和宿主回合。系统工具和宿主包装另外占用空间，因此 604 字节足以放下开发的必需正文时，整次模型请求仍超过 5 万字节。端点返回固定文本，这些请求各自的工具调用数为零。[宿主源码、请求与校准对照](composition-host.md)

收到选材回执后，研究运行器使用已有 C2 工作副本分别生成三组订单工作簿，每组独立执行东区、西区、跨区和只读四种账号。三个可导出账号生成具名 XLSX，只读账号均返回约定的拒绝结果。独立 Python 核验器三次都得到 A2、A3 通过，各组制品摘要与原始 C2 一致。对 C1 既有工作簿用相同核验器复查，付款时间 A3 仍通过，东区多出西区订单，A2 失败，结论为返工。回执分别列出宿主回合、研究运行器启动的脚本 Run、候选提交、脚本及制品摘要。这个实验测的是不同装配方案能否在同一工作契约下交付和核验，模型自行选用工具的行为留给下一阶段。[C1 核验报告](../topic-03a/fixtures/order-export-c1.json) · [C2 核验报告](../topic-03a/fixtures/order-export-c2.json)

## 复跑

从仓库根目录执行。需要 Git、Python 3.11+、XlsxWriter 3.2.9、openpyxl 3.1.5 和官方 Codex CLI 0.144.6。模型端点位于本机，输出目录使用新目录。主入口会重演排队后撤权。用宿主探针单独读取输出的 plan.json，则按最终复核后的计划重放。

```bash
work=$(mktemp -d)
python3 -m venv "$work/venv"
"$work/venv/bin/pip" install XlsxWriter==3.2.9 openpyxl==3.1.5
"$work/venv/bin/python" prototypes/topic-03b/composition/order_composition.py "$work/orders" --codex /absolute/path/to/codex
```

查看 summary.json 中的 dispatched_cases、changed_after_queue、host、verified_candidates 和 C1_control。CI 同时复跑 3A 基础回归、3B 的发布选版和项目知识实验，保存三个阶段各自的摘要。[CI 工作流](../../../.github/workflows/asset-release-research.yml)
