# 跨成员协作研究样例

以下人物、业务约定、交付标准及路径用于演练和解读固定样本。正式产品行为见[工作生命周期](../../architecture/01-unified-work-lifecycle.md)和[SOP 与研发工作流](../../architecture/02-sop-workflow.md)。

## 贯穿案例：订单批量导出

### 模拟约定

这个案例演示跨仓交付。林是产品成员，承担订单范围决定与业务验收。交付 Squad 主导实施，甲、乙、丙分别支持后端、前端和独立验证。周按已有共享安排提供 Leader 的 Runtime 和额度。

D1 约定导出当前筛选下的全部可见订单，包含跨页结果，格式为 XLSX，最多 5,000 条，超出时提示缩小范围。文件包含订单号、创建时间、状态及实付金额。D2 增加付款时间列，未付款留空，时区为 Asia/Shanghai。交付目标是可合入代码、获准的 UAT 环境和交付说明。

| 要求 | 需要的交付依据 |
|---|---|
| A1 范围 | 对照筛选条件、跨页订单和总数。 |
| A2 权限 | 以不同身份检查操作权限和订单可见范围。 |
| A3 内容 | 打开文件核对金额、付款时间及空值。 |
| A4 数量 | 5,000 条成功，5,001 条明确拒绝。 |
| A5 页面 | 检查空结果、加载、失败、重试与重复点击。 |
| A6 交付 | 核对集成基准、候选和 UAT 环境，记录指定成员的决定。 |

### 分工与接续

父 Issue 保存约定和林的决定。前端、后端子项可以并行，集成和独立验证子项先在 backlog 等待交付。丙调用局部 SOP 检查权限，报告交回 Leader。若乙的机器离线，后端可继续。乙交出补丁并确认旧进程停止后，可使用丁获准共享的机器接续，工程责任仍归乙。

### 从失败到交付

集成人形成候选 C1。验证报告显示金额和文件内容检查通过，但东区账号导出了西区订单。丙在验证子项交付失败报告，Leader 交回后端修正，让原集成、验证子项等待新候选。前端已交付的无关结果继续使用。

后端修正后，集成人形成 C2，丙按 D2 复验。现有样例报告覆盖 A2、A3。完整交付还需 A1、A4、A5 的材料，以及 A6 的 UAT 操作与决定。在材料齐备的案例分支，Squad 依工作流把父项交给林。林核对当前候选、标准与可访问的环境后接受，或指出不满足的要求并交还对应负责人。父项设置具名验收，并对该项关闭原生 PR 自动完成。[候选、报告与覆盖范围](workbench-walkthrough.md#按回执走查候选详情)

### 怎样复用这次发现

若退款项目也涉及按区域导出，原团队可以从失败报告提炼“分别核对本区与跨区账号可见数据”的方法。发布到团队前核对来源许可、适用范围与候选效果。退款项目负责人按本次权限口径选择版本，检查结果及用量记录在退款工作中。[经验贡献与发布](../topic-03b/knowledge-contribution.md)

### 最小路径：修改导出按钮文案

提出人在一个 Issue 写明目标页面和新文案。可自行修改，也可保留主责并评论请 Agent 协助，或把本项指派给 Agent。修改者交回变更和页面实际显示。本项约定提出人看过后接受时，由其在原 Issue 完成。项目已允许此类改动按规定检查完成且本项采用该约定时，有完成权的执行者或流程在检查通过后即可结束。若改动扩大到按钮可见权限，先由有权成员确认范围及完成要求。

## 订单批量导出的两条路径

两种做法共用同一[工作约定、角色和交付标准](#模拟约定)。林决定业务范围和最终接受，Squad 主导实施，丙对独立检查报告负责。

| 工作 | 首次探索，由负责人组织 | 方法成熟，由完整 SOP 托管 |
|---|---|---|
| 分工 | Leader 安排前后端和集成分工。收到候选 C1 后，丙在验证子项调用局部 SOP。 | 父 Issue 调用已发布的交付 SOP。有权负责人允许托管相应子项。前后端并行，集成等两份交付，验证等候选。 |
| C1 区域权限检查失败 | 局部 SOP 把失败交给丙，父 Leader 安排后端修正。前端已合格结果继续使用。 | 父流程按声明的返工目标重开后端及受影响的集成与验证。已结束的局部检查保留原记录。 |
| 形成新候选 C2 | 集成人交 C2，丙在原验证子项调用后继局部 SOP。 | 父流程保持原版本，引用 C2 对应的新子流程实例和有效检查。 |
| 交还业务负责人 | Squad 汇总对应候选的各项材料，按工作流交回林。 | 父流程对受托部分提交出口。要求具名接受时，原完成入口核对林的决定。 |

订单样例中已有报告只覆盖 C2 的区域权限和文件内容。若其余要求和 UAT 尚缺，显示对应缺项及处理人。材料齐备后，林可对 C2 和当前标准明确接受或退回。举例中的放行、等待与返工作用于所关联的候选。各生产、修正和检查 Run 按工作归属计量，父项与流程汇总按相同用量单元去重。[候选报告与覆盖范围](workbench-walkthrough.md#按回执走查候选详情)
