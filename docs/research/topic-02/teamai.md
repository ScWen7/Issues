# TeamAI · 可恢复的流程协议、版本与评测

研究基线为 `Tencent/teamai-cli@556b5246f2c13ad28b8b79b5b513a78ed8ab9dae`，2026-11-14 实际克隆并核对远端 `main`。从 CLI 的 start/next/report 跟到协议实现、图解释、两个 driver、本地状态写入、跨机交接，再从步骤报告跟到评测计划、Benchmark 和改进提案。下列“设计动机”是依据实现与反例的工程解释。

### T1 · 一张执行图可以服务多个 driver

**代码。** CLI start 先建立 Run，选择 local driver 时才继续驱动。协议在进程内把 next、report 接到同一个引擎。local driver 启动实际子进程，按工作目录互斥并控制并行度。skill driver 保存待报结果后通过同一协议提交，进程中断后可重发。设计动机是让无界面 CLI、交互宿主和外部执行者共享依赖、重试和状态语义，同时各自管理本地工具。**平台取舍。** SOP 解释器决定节点是否就绪，现有 Run 队列裁决执行领取，宿主仅报告这次尝试的事实。TeamAI 的协议给出可复用的职责拆法。[CLI 接线](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/index.ts#L856-L901) · [启动及驱动](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow-commands.ts#L600-L658) · [协议实现](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/protocol.ts#L650-L702) · [local 子进程及并发](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/drivers/local/local-driver.ts#L1085-L1136) · [skill 报告恢复](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/drivers/skill/tick.ts#L105-L120)

### T2 · 显式依赖决定哪些工作该继续

**代码。** 第二个及后续步骤须写 `needs`，空数组声明独立根。解析器检查未知依赖及环，表达式与模板的步骤引用在所在作用域校验。运行时等待所需依赖和读取项结算，再评判条件；失败依赖可被显式处置，独立分支仍可执行。测试让 build 失败，断言 test 跳过、docs 成功、整次流程失败。设计动机是把“前一步结束”“依赖被满足”“整次成功”变成三个可分别判断的事实。**平台取舍。** 用带结果条件的 DAG 决定节点推进，stage 只给人看阶段和接续位置。测试与文档能并行，验收需同时取得有效测试结果与候选制品。[解析依赖](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/parse.ts#L509-L532) · [验环](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/parse.ts#L2211-L2254) · [运行就绪及跳过规则](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/engine.ts#L934-L985) · [build / test / docs 断言](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/workflow-engine.test.ts#L701-L719)

### T3 · 领取、执行和回报有不同的并发约束

**代码。** `updateRun` 在 Run 文件锁内读、改并原子写回。引擎识别重复回报、已取消尝试、错误 attempt、旧版本和错误 driver。对仍有效的并行尝试，版本核对使用其租约签发时的 revision。同级节点推进使全局 revision 变化，另一份合法回报仍可提交。协议测试专门保留一个待投递节点和另一个已领取节点来验证这一点。设计动机是把写入串行化，同时允许执行并行。**平台取舍。** 中心存储负责事务和去重，本地持有领取凭据。以节点实例、尝试、租约代次和执行方检验回报，团队其他工作的进度只用于展示。重复回报应可找回已有回执，旧代次单独留痕。[存储与原子写](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/store.ts#L338-L371) · [报告校验顺序](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/engine.ts#L2888-L2930) · [并行回报测试](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/workflow-protocol-report.test.ts#L64-L89)

### T4 · 恢复时，最后一次写入也要检查进度

**代码。** 跨机接管以团队报告分支的既有快照写标识为条件替换快照，转换所有权，释放旧租约。最新提交修复了实际竞态：慢请求正在固定工作流文件夹，快请求已经接管并领取、取消或发布；慢请求随后安装旧快照。修复在最终写锁内再次核对本地已确认版本。六个组合测试覆盖首次接管和恢复时发生上述三种操作，逐项断言本地状态保留。设计动机是把可能耗时的文件读取放在锁外，同时确保锁外读到的状态没有覆盖新进展的效力。**平台取舍。** 用中心存储的所有权代次与条件更新承接该机制。本地材料准备完毕再核对代次、取消和进度。换人接管 Squad 协调与重新领取某个 Agent Run 分别处理。[快照条件替换](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/handoff.ts#L1075-L1104) · [旧租约移交](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/handoff.ts#L1156-L1191) · [最终安装二次核对](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/handoff.ts#L1284-L1358) · [竞态测试](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/workflow-handoff.test.ts#L132-L173)

### T5 · 重试影响消费旧结果的路径；交付失败单独恢复

**代码。** `retryContainers` 计算显式依赖、模板读取、循环等待、受影响工作目录及产物生产者的集合，逐层找出需要重算的步骤。旧 pass 归档，等待人工回应的请求随新 pass 重开，提交带旧 pass 的答案得到 `stale_response`。仅投递失败时重投相同分支，创建 PR 还有单独的未确认请求与查询路径。设计动机是同时解决两类代价不同的错误：用旧证据继续批准，或对已经成功的外部效果重复执行。**平台取舍。** C1 权限修复生成 C2 后，重跑消费该变化的测试、集成及审批，对保留分支逐项验证输入摘要。业务候选与标准版本由平台绑定；投递超时先查外部回执。[影响集合](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/run-controls.ts#L418-L469) · [重投与重新执行](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/run-controls.ts#L668-L700) · [人工答复校验](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/run-controls.ts#L221-L255) · [投递查证](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/engine.ts#L1915-L1945) · [拒绝后再次征求批准](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/workflow-run-controls.test.ts#L625-L634)

### T6 · 开始时固定可运行定义，交接时验证材料可取

**代码。** 选择生效的资源时按命名空间检测冲突；上一次有效的工作流定义可保留，与团队默认定义分开解析。启动时加载子工作流，固定文件夹，Run 保存 sourceHash、解析后的根及子定义。TeamPin 用 Git revision 与可选未提交补丁的摘要复原团队文件；另一台机器缺补丁或校验失败会报告缺失，缺少有效 Git 上下文时该实现读取当前 checkout。设计动机是支持成员在本地实验，同时让大多数有版本的材料可复查。**平台取舍。** SOP 与子定义固定内容版本，共享恢复所需输入保存到可授权读取的版本库或制品服务。角色映射、知识及工具版本由专题三解析，节点保存采用的引用清单。仅存本地的材料标出所在 Runtime 和替代输入要求。[资源冲突](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/resources/resolver.ts#L552-L575) · [缓存选择](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/cache.ts#L166-L181) · [固定整棵定义树](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/engine.ts#L1498-L1527) · [补丁复原及缺失](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/team-pin.ts#L79-L130) · [版本漂移试验](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/workflow-team-pin.test.ts#L80-L110)

### T7 · 运行事实、质量评分和业务验收各有写入点

**代码。** Run 开始和结束报告可先入本地队列，发布重放时结束记录优先。引擎通过 hook 为符合条件的已结算 pass 启动单独的评分 Run；评测启动失败留待后续处理。评分读取具体 run/step/pass 与该 Run 的 scorer 版本。CLI 用例断言原 Run 保持成功、没有 verdicts，另一条 `teamai-score` Run 产生标签。设计动机是允许事后评分、更换裁判和异步上报，同时保护原执行历史。**平台取舍。** 日常评分进入专题四；SOP 显式声明的阻塞质量门才影响后继节点；父 Issue 人工验收单独绑定候选、标准与授权人。检查工具自身超时或缺失与业务断言失败分别记账。[报告重放](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/workflow/records.ts#L327-L366) · [评测入口](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/scorers/engine-hooks.ts#L23-L34) · [评测主体与版本](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/scorers/score-plan.ts#L201-L245) · [检查结果分型](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/scorers/check.ts#L124-L144) · [独立评分 CLI 断言](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/__tests__/e2e/workflow-judge-loop.test.ts#L61-L76)

### T8 · 评测与改进同样用流程描述，生效需要新版本

**代码。** Benchmark 先生成试验定义，再独立启动评分，最后在 finally 汇总并可因回归失败。同一试题与重复次的比较会排除题目摘要变化，双方均由模型判定时还比对 rubric、工具、模型、effort 和评分方式（批量或单独）。默认自改进流程从可复现、尚未由回归题覆盖的失败中提取输入；达到门槛才在专有分支生成改动，交付为 PR。默认提示要求每个失败增加回归题；程序筛选输入，具体修改与题目质量交给改进 Agent。设计动机是让团队追溯某个流程改了什么、改善判断基于哪些样本。**平台取舍。** 导出候选、制品摘要、评测口径及失败样本交给专题四；治理通过后发布新 SOP 版本，仅在新的显式选择中生效。[Benchmark 流程](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/workflows/teamai-benchmark.yaml#L7-L57) · [比较准则](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/benchmark/pairing.ts#L38-L50) · [失败与已覆盖样本筛选](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/src/self-improvement.ts#L79-L109) · [提案阈值与交付方式](https://github.com/Tencent/teamai-cli/blob/556b5246f2c13ad28b8b79b5b513a78ed8ab9dae/workflows/teamai-self-improvement.yaml#L7-L36)
