# LoopForge · 图内推进、子流程与评测回路

研究版本为默认分支 HEAD `97b3cdc2f29a88e8767a8dc6c03bfb8865622653`。以下从 Issue 派发和直接启动两个入口进入同一个 Go 引擎，向下追到图调度、节点执行、SQL 租约与 Runner 任务，再从终态 Run 追到评测建议写回。这里的上游 `Run` 指一轮 SOP 执行，对应本项目的 SOP 实例。

1. **先确定委托范围，再决定哪条规则能启动下一步。** Issue 入口依请求、Issue、项目配置等解析 SOP。定时任务只取尚未跑过 SOP 的 Issue，同一 SOP 再跑要显式选择。一张 Issue 可以绑定多条 SOP，`appendSOPHandoff` 根据 `DependsOn` 或相邻顺序，给下一条 SOP 的输入追加期望交付物说明。这段代码没有读取前一步运行状态或核验文件。直接运行入口和 Issue 入口最终都调用 `StartWithRepositoriesContext`。**设计推断**：链路间保留人选择新一轮工作的自由，单轮内部才需要执行器强约束。**本项目**：Leader 按授权选择完整 SOP 或某个工作段；依赖若要阻止派发，须在调度侧检查前置结果和制品。 [Issue 路由](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/dispatch.go#L48-L95) · [Issue 到引擎](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/dispatch.go#L185-L211) · [多 SOP 交接文本](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/dispatch.go#L246-L285) · [直接运行](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/runs.go#L124-L145)

2. **启动时校验图并保存执行快照，重试存在局部更新入口。** `validate` 检查节点 ID、类型、返工目标、制品相对路径及重复名称；`validateDAG` 用入度拓扑遍历检查正向环路和悬空端点。引擎保存图、沙箱快照和每个节点的 pending 状态，再由持有执行权的进程启动。正常推进优先读取运行快照。重试、打回时 `overlayLatestNodeBindings` 会从目录覆盖受影响节点的 Agent、Executor、输出约定和失败策略，并可提高预算。停下来的实例还有显式刷新图的操作。**设计推断**：快照保留当时的流程结构，定向刷新方便修复配置后救回长任务。**本项目**：同版本返工记录新输入及新尝试；定义或固定角色、脚本等绑定升级时，经明确交接使用后继实例，原实例保留原定义及历史。 [校验器](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/workflow_graph.go#L155-L273) · [实例落库后启动](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/run_start.go#L149-L206) · [重试绑定覆盖](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/run_ops.go#L960-L995) · [主动刷新](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/run_ops.go#L818-L864)

3. **合流按所有直接前序成功判定，分支各自推进。** `WorkflowEdge.When` 声明为 success，`readyNodes` 只读取源、目标和前序节点状态。每个 ready 节点进入独立 goroutine，某分支结束即可放行自己的后继。一支审批或失败时，旁支仍可完成自己的下游。所有运行中的节点退出后，引擎再计算全图终态。**设计推断**：执行次序从真实依赖得出，慢分支只拖延消费它的节点。**本项目**：首版采用正向 AND 合流、显式门禁和受控返工；业务阶段显示进度。条件跳过、OR 合流需要新语义及独立用例。 [边模型](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/domain/workflow.go#L96-L101) · [就绪计算](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/workflow_graph.go#L11-L32) · [并发与收束](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_execute.go#L105-L184) · [失败和审批旁支测试](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/parallel_branches_test.go#L85-L146)

4. **门禁结果、重试和上游返工有不同后果。** Agent 结构化结果允许 pass、rework、fail、human；要求理由，human 还要求人工动作。rework 配有目标时直达上游，缺目标则转失败；有明确返工意见时跳过当前节点的常规重试。消耗完显式返工预算后交人裁决。`Reject` 重置目标和全部后代，停止其中正在执行的尝试；图外分支保留。节点层的 pass 继续执行后面的客观检查。**设计推断**：如果制品由实现节点生产，让评审者反复重试只会重复发现同一缺陷。**本项目**：记录技术执行结果、业务门禁结论、目标、预算和候选版本。节点内自修正沿用当前节点尝试并关联实际 Run，执行错误重试和跨节点返工使用新尝试；C1 权限缺陷交回有权修复的生产方，后继结果按适用标准重验。 [终态判定](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/gate_submit.go#L44-L104) · [客观检查顺序](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_execute.go#L840-L890) · [预算耗尽转人工](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_outcome.go#L50-L105) · [依赖失效范围](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/run_ops.go#L303-L355)

节点内还有独立的自修正循环：后置检查失败后，`onFailure=loop` 将错误写入反馈并继续下一轮，达到 `maxIterations` 或中断条件后退出；预算耗尽可转人工。此处的 iteration 与错误重试、跨节点 rework 分别记录。[自修正反馈与退出](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_execute.go#L938-L1007)。V0.2 对该路径进行了源码阅读，当前平台 Node Attempt 与 Run 的映射见[节点自修正、重试、返工与人工门禁](../../architecture/02-sop-workflow.md#8-节点自修正重试返工与人工门禁)。

5. **引擎用受检制品交接，代码更改还依赖工作区连续性。** 输出约定检查必需文件、普通文件和大小。对前序制品按节点、仓库、名字和路径取最新尝试；代码补丁只从直接前序传递。制品记录保留节点、attempt、SHA-256 和内容。远程 Runner 的补丁清单明确把共享工作区作为代码实况，普通制品则可以随输入交付。**设计推断**：文档可重建，工作区里的未发布改变有机器亲和性。**本项目**：跨成员交接引用已发布候选、哈希和可获取位置；单台机器上的目录另记归属。接手者凭证据复现输入后再续跑。 [输出检查](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/artifacts.go#L240-L268) · [版本选择与哈希](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/artifacts.go#L365-L415) · [Runner 输入构造](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_outputs.go#L167-L190)

6. **子 SOP 是独立实例，父节点保留关联并回收结果。** 启动时设置父 Run、父节点和工作区归属，恢复时优先重接已记录的 `ChildRunID`。引擎沿父链检查循环和深度，按输出名称导入最新子制品。代码先启动子实例再写回父节点；这是两个动作，断点测试覆盖父节点已有 child ID 后重接。**设计推断**：子流程可独立观察和恢复，父节点只消费结果。**本项目**：子实例创建带父节点和尝试的唯一键，重送命令或父进程中断可找到已创建的实例；C2 中子流程完成只交付父节点，父 Issue 的集成与验收另有决定。 [启动与回接](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/sop_node.go#L42-L134) · [嵌套校验](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/sop_node.go#L144-L173) · [子产物导入](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/sop_node.go#L243-L289) · [子成功而父失败的实测夹具](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/sop_node_test.go#L76-L118)

7. **调度租约、节点写回与执行任务各管一层。** Run 的 SQL 事务检查持有人、到期时间和 generation，换主后递增代际，续租核对 owner 和 generation。恢复扫描避让有效租约、保留人工等待和机器绑定。Runner 调用先写持久任务，执行端领取、续租并提交结果。节点提交时检查实例代际和活动状态；失败再比对 attempt，成功分支刻意允许同一代际的活动节点跨 attempt 报成功。**设计推断**：原实现用进程内同节点锁配合代际隔离，照顾同一调用续跑成功的情况。**本项目**：跨成员 Runtime 同时核对委托版本、实际尝试和候选引用，迟到消息存为历史证据；外部副作用另用幂等键或先核实结果再重试。 [SQL 租约](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/runs.go#L1101-L1152) · [恢复与工作区归属](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/run_recovery.go#L165-L225) · [结果提交条件](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/node_outcome.go#L30-L48) · [派 Runner 后等回执](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/engine/runner_dispatch.go#L258-L291) · [Runner SQL 领取](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/runners.go#L526-L575)

8. **项目占位与机器容量可以采取不同计数单位。** 云端顶层 SOP 按项目计数，个人机器按 Runner 配置，子 SOP 共享父实例的名额。各桶在短事务中顺序晋升等待项。上游测试将十个已启动实例改为 failed、waiting、cancelled，后来的实例仍排队，直到其中一项 succeeded。**设计推断**：此处计量的是保留给可恢复工作的名额。**本项目**：项目待办顺序、阻塞关系和机器执行槽位分开；已完成运行的节点和等待人工的节点释放执行槽，同一实例下一步重新竞争容量。 [配额与锁](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/run_admission.go#L15-L31) · [嵌套计数](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/run_admission.go#L179-L208) · [按桶晋升](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/run_admission.go#L383-L421) · [占位测试](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/repo/run_admission_test.go#L59-L104)

9. **评测有从轨迹到资产修改的实际调用链。** 终态 Run 才能启动评测。后端提取各节点尝试、返工、工具重复、错误、耗时和制品；把摘要和策略交给模型，由后端根据维度分重新计算总分。另一个 API 接受使用者选定的建议 ID，记录逐项结果，对受支持的操作更新项目 Workflow 或 Agent；通用模板在该流程中取得项目副本。**设计推断**：一次执行产生诊断材料，修改可复用流程是独立操作；应用建议仍需后续样本检验。**本项目**：专题二从第一天记录节点、候选、输入、尝试与失败分类。评测引用这些数据，交给资产治理形成新版本，保留在途实例的原判据。 [终态入口](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/run_eval.go#L80-L141) · [事实提取](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/runeval/facts.go#L50-L116) · [聚合评分](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/runeval/prompt.go#L40-L75) · [逐项应用及项目副本](https://github.com/Tencent/LoopForge/blob/97b3cdc2f29a88e8767a8dc6c03bfb8865622653/internal/httpapi/run_eval.go#L243-L365)
